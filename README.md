# reels-assembly-tools

세로 영상(릴스)을 **코드로 조립**하는 도구 7개. 훅을 만들고, 생성형 클립을 이어붙이고, 첫 3초를 검사합니다.

## 먼저 — 이건 발행 도구가 아닙니다

클론해서 돌리면 **mp4 파일이 나옵니다.** 올라가지는 않습니다.

세로 영상은 트렌드 음원 때문에 API 로 못 올립니다. 그래서 **올리는 건 폰에서 사람이** 합니다. 이 저장소의 범위는 **「영상 파일까지」**입니다.

## 왜 코드로 조립하나

생성형 AI 로 만든 클립에는 **워터마크가 박혀 나옵니다.** 제 계정에는 그걸 끄는 설정이 없었습니다.

편집 도구 안에서 통째로 이어붙이면 그 워터마크가 **전 구간에** 남습니다. 우리가 만든 훅 화면까지요.

그래서 **훅은 우리 쪽에서 만들고, 생성형 클립만 따로 이어붙였습니다.** 그러면 워터마크가 생성 구간에만 갇힙니다. 지우는 게 아니라 가두는 겁니다.

## 도구 7개

| 파일 | 하는 일 |
|---|---|
| `cardnews/assemble-reel.mjs` | 훅 + 생성형 클립을 이어붙인다 (이 저장소의 중심) |
| `cardnews/render-reels.mjs` | 대본에서 훅 화면을 렌더한다 |
| `cardnews/hook-check.mjs` | 첫 3초에 훅이 실제로 있는지 검사 |
| `cardnews/reel-review.mjs` | 프레임 밝기·길이 자기검사 |
| `cardnews/make-brand-sting.mjs` | 끝에 붙는 워드마크 스팅 |
| `cardnews/check-sources.mjs` | 쓰인 원본 소스가 기록돼 있는지 |
| `cardnews/run-render-reels.cmd` | 위를 묶어 도는 래퍼 (Windows) |

## 실제로 걸렸던 것들

**같은 걸 재는 자를 클립마다 새로 맞춰야 했습니다.** 워터마크 픽셀을 세는 임계값을 전 클립에서 쓰던 값으로 두었더니, 어두운 클립에서 **생성 구간마저 0개**로 나왔습니다. 워터마크 밝기가 임계보다 낮았던 겁니다. 그대로 썼으면 「워터마크가 없다」는 거짓 결론이 나왔습니다.

**화면에 숫자를 새기면 그 숫자가 바뀝니다.** 측정값을 영상에 얹고 다시 인코딩하니 값이 미세하게 달라졌습니다. 새기고 → 다시 재고 → 같은 값이 나올 때까지 수렴시켰습니다. **패널 숫자는 최종본에서 확정해야 합니다.**

**「무음」과 「오디오 트랙 없음」은 다릅니다.** 두 클립을 이어붙일 때 한쪽에 트랙이 없으면 연결이 깨집니다. 그리고 소스마다 샘플레이트가 달라서(44.1k / 48k) 맞춰주지 않으면 같은 자리에서 깨집니다.

**효과음을 기본값으로 뒀습니다.** 훅 구간이 무음이면 발화 구간과 큰 음량 차이가 생겼습니다. 결정을 문서에만 적으면 다음에 잊어서, **끄려면 명시해야 하는 쪽**으로 코드에 박았습니다.

## ⚠️ 쓰기 전에 바꿔야 할 것

**해상도.** 기본값은 **1080×1920** 입니다. 처음엔 720×1280 이었는데 올렸습니다.

720 으로 둔 이유는 *"업스케일은 손실이고 플랫폼이 어차피 깎는다"* 였습니다. 그런데 재보니 **우리 화면에서는 잃을 게 별로 없었습니다** — 훅과 플레이트가 2D 그래픽이라 평평한 색면이 대부분이고, 업스케일로 깎이는 고주파가 원래 적었습니다. 반대로 720 으로 올리면 플랫폼이 한 번 더 깎아서 그쪽 손해가 더 컸습니다.

⚠️ **실사 푸티지를 쓰신다면 이 판단이 그대로 적용되지 않습니다.** 위 측정은 2D 그래픽 기준입니다. `--w` · `--h` 로 조정하세요.

**⛔ 구글 드라이브 업로드가 기본으로 켜져 있습니다.** `assemble-reel.mjs` 는 조립이 끝나면 곧바로 `rclone` 으로 영상을 올립니다.

올리는 이유는 **폰이 거기서 받기 때문**입니다. 로컬에 mp4 가 있어도 드라이브에 없으면 그날 올릴 영상이 폰에 없습니다. 한 번 그래서 하루를 날렸습니다.

원격 이름 기본값이 **`gdrive:dhenddl-reels` — 제 것**입니다. 그대로 돌리면 없는 원격을 찾습니다.

```bash
node cardnews/assemble-reel.mjs ... --no-drive              # 업로드 끄기
node cardnews/assemble-reel.mjs ... --drive '내원격:내폴더'   # 내 것으로 바꾸기
```

⚠️ 업로드가 실패해도 **조립은 실패로 처리하지 않습니다** — 영상은 이미 만들어졌으니까요. 대신 손으로 올릴 명령을 찍어줍니다.
📌 파일명 규칙은 `<발행일>-<원래 파일명>` 입니다. 이름 정렬이 곧 발행 순서가 됩니다.

**브랜드 문자열.** 스팅과 훅 배지에 제 계정 이름이 들어갑니다. 위 드라이브 원격 이름도 같습니다. 쓰시기 전에 훑어보고 바꾸세요.

**대본 경로 규칙.** `cardnews/lines-path.mjs` 가 경로 규칙을 들고 있습니다. 화면 대본은 `cardnews/lines/<슬러그>.txt`, 내레이션은 `cardnews/narration/<슬러그>.txt` 입니다. 저장소 안 도구가 이 파일을 import 하므로 같이 들어 있고, 그대로 두면 됩니다. 다른 위치를 쓰시려면 이 파일을 고치세요.

## 필요한 것

npm 의존 **두 개**입니다.

- `ffmpeg-static`
- `playwright` (훅 화면 렌더용)

그리고 **`ffmpeg` 외부 바이너리**가 필요합니다. `ffmpeg-static` 이 대부분 해결하지만 환경에 따라 별도 설치가 필요할 수 있습니다.

```bash
npm install
npx playwright install chromium
```
